# 共同原则：简洁界面与可组合能力

> 适用：未来 R01–R08 的设计、执行计划和验收。
>
> 状态：目标约束，尚不表示当前界面已经符合全部要求。

## 1. 一个页面围绕一个明确任务

解压任务完成一批解压，压缩任务创建一批压缩包，浏览任务查看一个归档的内容。每个页面只有一个当前阶段的主要动作，如“开始解压”“开始压缩”“提取所选”。

用户输入很多文件不等于需要很多配置。复杂的调度、路径检查、资源计量和失败汇总由业务层负责。文件仍由用户显式开始处理，不在拖入后自动写入或自动执行串联任务。

不增加要求用户先学习全部功能的总控制台、流程图或多页配置向导。跨任务入口带入已知结果，仍让用户看到输入、目标和开始动作。

## 2. 信息分为三个层次

| 层次 | 放什么 | 例子 |
| --- | --- | --- |
| 默认可见 | 判断此次任务需要的最少信息 | 输入、产物名称或位置、主要动作 |
| 按需出现 | 偶尔需要且直接改变结果的选项 | 解压层数、分别打包、密码、文件类型筛选 |
| Headless / Workflow | 面向程序调用和组合的细节 | 复杂规则组合、资源参数、跨插件调度 |

“更多选项”中的内容仍须按当前任务组织，不能收纳所有底层参数。对于预算、线程、字典大小等技术参数，优先采用经过验证的默认策略；GUI 不为 API 每个字段都提供控件。

设置和运行详情分开。主界面简洁时，失败原因、已完成输出和可采取的行动仍须可见。

## 3. 默认行为与可发现性

| 项目 | 目标默认行为 |
| --- | --- |
| 解压深度 | 一层；开启“继续解压内部压缩包”后再显示总层数 |
| 递归开关 | 初次开启建议总层数 2，上限仍为 16；不改变 TAR 组合归档计层规则 |
| 压缩格式 | ZIP；首版固定，增加其他已验证格式后再提供轻量选择 |
| 压缩级别 | 标准；确有需求时在更多选项提供仅打包、快速、高压缩等语义选项 |
| 压缩分组 | 全部合成一个包；“分别打包”按需选择 |
| 输出位置 | 明确可见，建议值可修改；无法可靠推导时要求选择 |
| 输出命名 | 提供确定、可解释的建议；冲突自动编号并显示实际产物 |
| 源文件 | 保留源文件、源归档和已有成功输出 |
| 密码 | 默认不设置；当前任务内使用，无跨任务自动继承或持久化 |

上表是未来目标，详细计划应明确建议路径与建议名称的算法。不得使用隐藏的工作目录、隐式持久历史或不可见的规则替用户决定输出。输出位于输入目录内时必须排除本次目标和临时内容，防止再次打包自身。

递归、分别打包等核心能力需要一次明显操作即可发现。简洁不能通过删除已确认需求或将全部功能藏到多层菜单实现。

## 4. 随状态变化展示内容

| 状态 | 首要内容 | 附加内容 |
| --- | --- | --- |
| 空状态 | 拖放区域和添加入口 | 一句说明支持的任务 |
| 待开始 | 输入摘要、输出目标、开始 | 移除和按需选项；必须处理的冲突就地提示 |
| 运行中 | 当前项、真实进度、取消 | 可展开任务明细；冻结本次输入 |
| 已完成 | 成功数量、打开结果 | 文件大小、用时等可用信息 |
| 部分失败 | 成功产物和失败摘要 | 在相关项补密、重试或调整后新建任务 |
| 已取消 | 已提交与未完成数量 | 清理残留的准确位置和可用产物 |

取消后等待实际工作退出，不立即显示完成。迟到回调不能修改新任务或已关闭页面。没有可靠总量时显示已处理数量与当前项，不编造百分比、预计结束时间或压缩后大小。

## 5. 结果语义与文件处理

每个独立归档或明确的整理产物有自己的提交边界：临时写入、完成必要检查、以不覆盖方式提交。压缩文件、解压目录、整理目录可以共享原则，不强迫它们使用相同事务实现。

成功表示该产物完成其声明的检查，不能自动解释为所有后代、所有格式认证或整批任务均已成功。对于 RAR5 加密等现有校验限制，保留可见说明。

筛选和整理默认生成新产物；不移动、删除或修改用户已有源文件。计划预览与执行期间来源发生变化时，不继续套用失效的选择和命名映射。

## 6. 工程边界

- Headless 承担规则、输入快照、任务执行、进度和结果，不引用 Avalonia 或 Plugin SDK。
- Plugin 使用公开 SDK 组织 Document 与跨插件适配；Standalone 复用真实实现。
- 压缩、解压、浏览、整理按用例分责，避免在 `UnpackService` 中堆积模式开关。
- 只在确有共同语义时提取路径、命名、取消、诊断等共享组件，不提前建立通用归档框架。
- 解压候选密码池与压缩目标密码分开建模；重打包来源密码不能自动成为目标密码。
- 同一插件可同时打开多类任务，参数、密码和可变运行状态按会话隔离。
- 可创建格式与可读取格式分开维护，浏览、选择提取、加密、校验等能力也须按证据区分。

## 7. 每阶段的简洁性验收

详细计划必须选取普通任务、批量任务、失败恢复三个代表场景，并逐项记录：

1. 首次打开默认看到哪些控件，每个控件为何必要。
2. 普通任务在不展开更多选项时能否完成；不可省略的选择是什么。
3. 递归、分组、密码等能力是否有明确入口，完成后是否自动增加下一次任务的负担。
4. 失败项是否提供准确原因和下一步，成功产物是否仍可直接访问。
5. 窄窗口、深浅主题、键盘导航、DPI 下主要操作是否可见且可用。
6. 新选项能否通过默认策略或上下文入口代替；必要选项的默认值和影响是否清楚。

可以记录点击次数、用户需要作出的决定数和误操作，但不预设虚构的使用数据。性能阈值根据真实样本与环境制定，不以固定秒数代替内容正确性。
