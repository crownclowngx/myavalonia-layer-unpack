# R03：批量打包与加密

> 状态：已实施／本地验证通过，部分原生交互与桌面工具待验收，详见 [G0009 结果](../refactoring/G0009/result.md) · 实施映射：G0009
>
> 前置：R02 的 ZIP 创建、输入清单与文件提交闭环。
>
> 产出：一次处理多份交付资料，选项仅在需要时出现。

实施档案：[计划](../refactoring/G0009/plan.md) · [方案](../refactoring/G0009/implementation.md) · [批次契约](../refactoring/G0009/batch-creation-contract.md) · [格式矩阵](../refactoring/G0009/encryption-and-compression-matrix.md) · [交互](../refactoring/G0009/interaction-design.md) · [验收](../refactoring/G0009/acceptance-matrix.md)。

实际边界：分别输出须在所有来源目录之外；目录排除按命中目录计一项并包含后代；AES“仅打包”采用 Deflate 0。两套库的精确版本与读取方式已验证，桌面工具原生互操作仍待验收；不承诺系统自带工具支持。

## 1. 用户目标与主流程

用户加入十个资料文件夹，选择“分别打包”，开始后得到十个对应 ZIP；需要加密时展开密码输入，需要排除内容时选择简单规则。

普通用户继续使用 R02 的默认路径，不必先选择任务模式、压缩算法或密码策略。

## 2. 推荐实施顺序与范围

本阶段可以拆为“分组打包与简单规则”“ZIP 加密”两个实施单元，各自形成可验收产物。

| 能力 | 用户行为 | 默认与边界 |
| --- | --- | --- |
| 分组 | 全部合成一个包／分别打包 | 默认合成；分别模式以选中的顶层项分组，文件夹后代属于同一组 |
| 命名 | 根据各组名称产生对应 ZIP | 同名自动编号；批次开始前可查看输入到输出的对应关系 |
| 排除 | 按文件类型或目录名排除 | 默认不排除；只在展开后设置，显示排除数量与查看入口 |
| 压缩偏好 | 标准／快速／高压缩／仅打包 | 默认标准，放在更多选项；准确映射到已验证写入能力 |
| 加密 | 为本次输出设置一个密码 | 默认关闭，同批次目标包使用明确设置的同一密码 |

不默认排除隐藏文件或名称看似临时的用户资料。规则语法、大小写、目录匹配与子目录传播由详细计划明确；GUI 采用有限选择，复杂表达式不进入普通页面。

## 3. 分组与失败规则

- 批次开始时冻结分组和输入清单，普通目录嵌套不产生额外输出组。
- 合并模式产生一个事务；分别模式每组独立提交，单组普通失败不影响其他独立组。
- 重叠输入按照 R02 的明确规则处理，不因切换分别模式静默改变收录内容。
- 规则排除全部内容的组显示“无可打包内容／已跳过”，不默认生成空壳包或计为成功。
- 成功组保持可用；重试只作用于允许重试的失败组，源变化时重新确认输入并新建相应任务。
- 默认继续采用可预测的调度，不向 GUI 暴露并发数。并行优化需要独立的资源和内容证据。

## 4. 密码与互操作

优先评估 ZIP AES-256 的创建和目标工具兼容性，验证后才开放入口。简单说明“接收方工具需要支持此加密 ZIP”，不要在未验证前承诺系统自带工具一定可打开。

压缩目标密码与解压候选池分开：不尝试候选、不继承其他任务成功密码、不自动将来源密码用于目标。UI 密码输入默认遮蔽，可临时显示；是否采用重复输入等防误输方式在详细计划中明确。

密码仅属于当前创建会话，不写入配置、日志、结果序列化或历史。ZIP 内容加密不能宣称文件名也已隐藏，文件名可见性应在入口说明。加密格式的认证验证必须使用真实正确密码、错误密码及损坏样本。

## 5. 工程切入与阶段交付物

复用 R02 的单包创建用例，在外层增加分组计划与批次结果，不在写入器内部承担输入分组。密码通过独立的秘密字段传入写入适配，不混入可记录的普通任务描述。

详细计划交付：分组和排除规则、包内路径预览规则、各级失败边界、重试契约、压缩偏好映射、加密与目标工具矩阵，以及默认／展开／失败状态的界面方案。

## 6. 验收场景

| 编号 | 场景 | 阶段出口要求 |
| --- | --- | --- |
| R03-AC01 | 多文件夹分别打包 | 一组一个 ZIP，后代正确收录，名称与来源对应 |
| R03-AC02 | 同样输入采用合并模式 | 仍生成一个 ZIP，默认任务路径未增加必选项 |
| R03-AC03 | 排除部分与全部内容 | 结果与可检查规则一致；空组明确跳过，不静默丢资料 |
| R03-AC04 | 一个组读取失败，其他组正常 | 失败边界准确，其他组成功产物保留 |
| R03-AC05 | 加密创建，正确与错误密码读取 | 正确密码得到原始内容；错误密码不产生成功输出 |
| R03-AC06 | 认证损坏与跨工具读取 | 认证异常被发现；兼容性与已验证工具、版本相对应 |
| R03-AC07 | 失败组重试与批次中途取消 | 已成功包不重复创建；取消项与失败项分别处理，仅重试声明可恢复项 |
| R03-AC08 | 两个压缩会话与一个解压会话 | 密码和分组互不继承，可序列化结果不含秘密 |
| R03-AC09 | 零字节输入统计与不可压缩数据 | 统计准确，无除零或虚构节省空间 |

## 7. 非目标与阶段出口

不包含每文件独立密码、密码管理器、规则脚本编辑器、自动历史预设、分卷、7z 加密或跨重启队列。ZIP AES 不能满足特定目标工具时，可明确保留普通 ZIP 并收缩该加密变体，不以未认证输出代替成功。

阶段出口是分别打包、简单规则和已声明加密能力形成用户闭环，普通 ZIP 仍保持 R02 的简洁路径。后续 R06 可以调用分组和目标密码契约，来源与目标秘密继续分离。
