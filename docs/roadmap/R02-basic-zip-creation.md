# R02：基础 ZIP 压缩

> 状态：已实施／本地验证通过，部分原生交互待验收 · 实施映射：[G0008 计划](../refactoring/G0008/plan.md) · [结果](../refactoring/G0008/result.md)
>
> 前置：R01 简洁交互和当前解压基线。
>
> 产出：同一插件内拥有可独立使用的“压缩任务”和“解压任务”。

## 1. 用户目标与主流程

用户添加文件和文件夹，检查自动建议的压缩包名称与位置，点击“开始压缩”，得到一个 ZIP。默认格式为 ZIP，压缩级别为标准，无需理解底层算法。

本阶段只交付“全部合成一个包”的完整切片。批量分别打包、密码和更丰富选项在 R03 加入。

## 2. 交付范围

- 添加与拖入一个或多个本地文件、文件夹，支持移除和清空。
- 自动建议 ZIP 名称和输出位置，用户可修改；显示最终目标。
- 保留声明范围内的目录结构、文件内容和空目录，中文名称可互操作。
- 一个 ZIP 的扫描、写入、收尾提交、取消、失败和打开产物形成完整状态流。
- 运行中显示已处理量；压缩完成后可展示输入文件字节总量、归档大小和耗时。
- 通过 Headless 执行相同创建用例，无需 Avalonia 或 Host。

界面默认只突出输入、目标、开始压缩。格式固定为 ZIP 时不提供只有一个选项的格式下拉框；标准压缩级别不要求用户先确认。

## 3. 输入与输出规则

| 问题 | 目标规则 |
| --- | --- |
| 包内层级 | 以选中的顶层项组织：文件保留文件名，文件夹保留该文件夹及后代 |
| 父目录与子项重复加入 | 规范化扫描清单，避免同一来源在包内重复出现；执行前说明被合并的输入 |
| 多来源同名根项 | 形成可检查的唯一包内名称或在开始前提示解决；不能静默覆盖或丢弃 |
| 输出与输入重叠 | 排除本次 ZIP、暂存文件及事务目录，防止把正在生成的包再次收进输入 |
| 已有目标名称 | 不覆盖，自动编号，结果显示实际路径 |
| 源文件变化或读取失败 | 不把不完整 ZIP 标记为成功；按声明策略终止该包并报告原因 |
| 提交与取消 | 同一目标文件系统内暂存，完成写入与归档收尾后不覆盖提交；失败清理未提交文件 |

扫描和写入均受有限资源约束，链接、重解析点和特殊文件的支持边界与现有路径策略对齐。输入发生变化的检测能力与局限应说明，不宣称跨多个文件的全局快照一致性。

目标在源目录内部的合法使用场景仍需准确排除本次自有产物；存在无法安全判断的重叠时，在写入前给出明确原因。

## 4. 工程切入与阶段交付物

新增独立压缩用例、请求与结果、归档写入适配器和文件提交事务。现有 `IArchiveExtractor` 继续承担解压，不扩成含大量开关的双向接口。

复用路径检查、命名、取消和诊断的共同部分；压缩预算根据源字节、条目与归档输出计量，不直接套用解压膨胀预算。

Plugin 增加压缩 Document 注册与稳定 ID，Standalone 能预览两类真实任务。保持现有解压 Document 和 Plugin ID，测试应从 V1 的单 Document 断言更新为实际目标贡献。产品显示名可在此阶段调整为“压缩包工作台”。

详细计划交付：创建契约、输入到包内路径的映射、写入引擎取舍、事务与源变化规则、UI 状态、真实 ZIP 样本和互操作矩阵。优先评估已有运行时和依赖，不因新增写入用例直接更换解压引擎。

## 5. 验收场景

| 编号 | 场景 | 阶段出口要求 |
| --- | --- | --- |
| R02-AC01 | 若干普通文件与文件夹 | 默认操作生成一个 ZIP，包内路径、空目录及内容摘要符合清单 |
| R02-AC02 | 中文、空文件、长路径和大量小文件 | 支持范围有真实证据，超出范围明确失败 |
| R02-AC03 | 父子输入重叠与多来源同名 | 无重复收录、覆盖或丢失，命名可解释 |
| R02-AC04 | 目标位于选中源目录中 | 不收录当前归档和临时文件，扫描不会无限增长 |
| R02-AC05 | 目标已存在、并发同名创建 | 既有文件不变，两个产物可分别定位 |
| R02-AC06 | 读源失败、源变化、磁盘写入失败 | 不提交伪成功产物，诊断准确，源文件保留 |
| R02-AC07 | 真实写入中取消、关闭页面 | 未提交 ZIP 清理，会话退出，无迟到进度污染 |
| R02-AC08 | 生成包由独立读取器或目标工具打开 | 文件清单与内容匹配；同时核对现有解压用例兼容性 |
| R02-AC09 | 压缩与解压两个任务同时存在 | 各自可执行与关闭，业务不共享可变会话状态 |

压缩后可能比输入更大，界面如实展示；空输入不开始，零字节文件组成的合法归档不产生除零统计。

## 6. 非目标与阶段出口

不包含分别打包、加密、7z / RAR 创建、分卷、自解压 EXE、压缩包追加修改和文件管理器功能。

ZIP 大文件／Zip64、时间戳等元数据的声明范围在引擎验证后写入创建矩阵；未经验证的变体不能通过 ZIP 名称笼统承诺。

完成标准是用户可直接创建和使用普通 ZIP，Headless 与 GUI 共用同一规则，现有解压回归成立。R03 以此稳定创建用例扩展分组与加密。
