# R05：输出整理

> 状态：已实施／347 项测试与完整本地门禁通过，部分原生交互待验收 · 实施映射：[G0011](../refactoring/G0011/result.md)
>
> 前置：R04 的明确选择语义、现有递归解压与结果清单。
>
> 产出：将已解压资料整理到结构清楚的新目录。

实际范围、规则及生命周期见[整理契约](../refactoring/G0011/organization-contract.md)、[交互专项](../refactoring/G0011/interaction-design.md)和[验收矩阵](../refactoring/G0011/acceptance-matrix.md)。当前输入为 UnpackResult 已提交清单，整理作为解压结果的临时子页；后续目标与原阶段要求保留如下。

## 1. 用户目标与主流程

用户完成一批解压后，点击“整理结果”，选择“提取 PDF”等少量明确规则，查看将生成的目录摘要，开始后得到独立整理目录。

每次仍处理一个明确整理任务，不提供任意操作拖连的流程编辑器。原解压默认行为保持不变；自动整理不作为每次解压的隐含步骤。

## 2. 推荐实施范围

| 能力 | 目标行为 | 默认策略 |
| --- | --- | --- |
| 类型提取 | 按用户选定文件类型提取，如 PDF、图片 | 不自动筛选；展开后选择，名称含义明确 |
| 按来源归类 | 按顶层来源包组织资料 | 保留来源边界，不把不同来源混进同名目录 |
| 去掉多余层级 | 压平只有一个普通目录的连续包装层 | 默认关闭；预览中说明哪些路径将变化 |
| 冲突处理 | 展示同名或大小写冲突及建议名称 | 不覆盖、不丢弃，输出名称映射可检查 |
| 整理结果 | 生成新的文件与目录清单 | 原来源和原解压结果保留 |

先完成“按类型提取并按来源归类”，再增加目录层级简化。类型筛选基于明确规则，首版按扩展名时应说明，不把它描述成内容识别。

首版输入优先来自当前解压任务的已提交结果与来源记录。脱离结果上下文的任意目录整理可另列后续扩展，避免本阶段演变为通用文件管理器。

## 3. 来源与目录规则

- 输入清单来自已成功提交的结果，不重新扫描整个输出根以接管过往文件。
- 当前结果中同一路径只处理一次；区分外层解出的嵌套归档与该归档的展开目录，避免重复收集内容。
- 明确是否纳入嵌套归档文件本身。建议普通资料类型筛选只收录匹配文件，默认的全文件整理不擅自删除或隐藏归档。
- 去掉单层目录必须有精确定义：仅一条普通子目录链、无同层其他条目、不跨来源边界、不改变文件名。
- 多来源合并与改名先生成目标映射，执行前可展开查看；大量项目默认展示摘要，冲突和异常突出显示。
- 预览后来源变化时验证并拒绝失效映射，不把新的或被替换文件悄悄纳入执行。
- 通过复制生成新目录，暂存后提交；取消与失败只清理本次未提交内容。

不以自动移动、覆盖或删除来源实现去层级。普通文件复制仍要验证路径、链接、读取错误、空间和取消，不能因为已解压成功就跳过本次检查。

## 4. 工程切入与阶段交付物

Headless 增加“生成整理计划”和“执行整理计划”的职责，输入包括文件清单、来源关系和有限规则，输出包括目标路径映射、冲突和结果。

现有 `UnpackResult` 以归档节点为主；执行计划需核对是否已有可用文件清单，必要时通过明确契约提供，不让 UI 推测内部临时目录或扫描历史产物。

界面作为解压结果的上下文动作进入。是否复用当前 Document 的临时子状态或新建独立整理 Document，在详细计划中根据任务并存与关闭责任确定；不增加常驻工具栏面板。

交付物包括：整理规则、来源模型、映射预览、源变化与冲突策略、复制事务、生命周期以及包含复杂目录的真实验收样本。

## 5. 验收场景

| 编号 | 场景 | 阶段出口要求 |
| --- | --- | --- |
| R05-AC01 | 多个来源只提取 PDF | 仅收录匹配文件，按来源组织，内容摘要保持一致 |
| R05-AC02 | 存在嵌套包及展开结果 | 同一文件不重复复制，来源归属明确 |
| R05-AC03 | 连续单子目录与含额外文件目录 | 只简化符合规则的链，不丢同层文件 |
| R05-AC04 | 同名、大小写和不同来源冲突 | 预览与最终命名一致，已有文件不覆盖 |
| R05-AC05 | 预览后来源改变或消失 | 不执行失效映射，给出可操作诊断 |
| R05-AC06 | 无匹配内容 | 明确提示，无伪成功整理目录 |
| R05-AC07 | 复制中失败或取消 | 原始包和原解压结果不变，未提交整理内容清理 |
| R05-AC08 | 大量文件 | 摘要可用、详情可展开、页面响应与资源有实测记录 |

## 6. 非目标与阶段出口

不包含内容去重、全盘扫描、文件语义分类、自动删除嵌套包、批量重命名脚本、同步备份和原地整理。复杂规则组合留给 R08 的工作流，不在页面上增加通用规则语言。

完成标准是“输入结果清单 → 可检查的目标映射 → 新整理目录”闭环成立。R06 可以把整理后的明确清单交给创建用例，不需要重新猜测要打包哪些文件。
