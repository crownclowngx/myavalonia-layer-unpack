# R06：格式转换与重新打包

> 状态：规划中 · 实施映射：未分配
>
> 前置：R02 创建、R04 枚举／选择；整理后打包依赖 R05，分别打包／目标加密依赖 R03。
>
> 产出：将现有归档或整理结果生成新的 ZIP，提供清楚的来源到产物对应关系。

## 1. 用户目标与主流程

本阶段围绕两个明确入口交付：

1. 用户选择一批已支持读取的归档，执行“转换为 ZIP”，每个来源生成一个新 ZIP。
2. 用户在解压或整理结果上执行“打包结果”，检查带入的文件与目标后开始创建。

随后才组合有限的“解压 → 整理 → 打包”操作，例如解开两层、提取 PDF、按来源生成 ZIP。复杂任意流程留给 R08。

## 2. 范围与默认交互

| 操作 | 默认规则 | 按需选项 |
| --- | --- | --- |
| 转换为 ZIP | 一个来源对应一个新包，按包内原有结构转换 | 目标位置；来源密码与目标密码分开 |
| 打包结果 | 带入明确已提交的文件或整理清单 | 合成或分别；仅在对应能力已实施后出现 |
| 整理后打包 | 使用选定的有限整理规则形成新内容清单 | 总解压层数、类型筛选、来源归类 |

默认格式转换不递归展开内嵌归档；内部 ZIP / RAR 作为普通文件保留。用户选择“展开内部包再打包”时，属于内容结构转换，明确显示层数和结果规则。

从现有页面传入文件后仍由用户点击开始，不因进入新任务自动写入。只有显式选择复合操作时才在该任务内部继续执行后续步骤。

## 3. 内容、密码与提交语义

- 格式转换实际是读取来源、重建目标，不通过更换扩展名实现。
- 文件内容、声明支持的相对路径和空目录是基本保留对象；时间戳、权限、链接、注释等元数据单独声明支持与限制，不笼统承诺完全无损。
- 不支持的条目类型在执行前或读取时明确报告；不得静默丢弃后仍宣称完整转换。
- 来源解密密码与新包密码分别提供，默认目标不加密；不得自动复制来源密码或把候选池作为创建密码。
- RAR5 加密等来源校验限制传递到转换结果，不因能创建 ZIP 就显示来源已充分验证。
- 每个目标包完成必要写入和校验后单独提交；一个来源失败不撤销其他已成功产物。
- 临时展开、整理和打包空间统一规划与计量，不把多个独立预算简单重置后当成整项资源上限。
- 仅清理本复合任务拥有的未提交临时内容，不清理用户已有解压目录或此前成功提交的结果。

若用户选择保留中间产物，输出应在开始前明确；默认中间内容属于本任务临时工作区，完成或取消后清理，并准确报告清理残留。

## 4. 工程切入与阶段交付物

新增有限的复合用例，调用已有读取、选择、整理、创建能力。复用稳定契约，不在界面代码内串接文件系统操作，不复制另一套递归和密码处理。

只有真实格式验证证明可行时才优化为流式转换；默认采用可解释的暂存与提交方案。针对固实格式、加密头或输出需可定位流等约束，不能预先承诺无临时磁盘。

详细计划交付：转换与递归重打包的语义区别、内容／元数据保留矩阵、来源和目标秘密契约、总体资源计量、阶段进度、取消和清理责任，以及页面衔接方案。

## 5. 验收场景

| 编号 | 场景 | 阶段出口要求 |
| --- | --- | --- |
| R06-AC01 | 多个受支持 RAR / 7z 转 ZIP | 每来源对应一个 ZIP，声明内容和路径经独立核对 |
| R06-AC02 | 来源内含 ZIP，普通格式转换 | 内部 ZIP 字节保持一致，不自动展开 |
| R06-AC03 | 明确选择展开两层后打包 | 深度、分支及整理规则与现有用例一致 |
| R06-AC04 | 来源密码 A，目标密码 B | 两类密码不混用；未设置目标密码时不继承 A |
| R06-AC05 | 一个来源损坏或认证受限 | 失败或受限状态准确传递，不误报整批完整成功 |
| R06-AC06 | 任一步骤中取消或写入失败 | 已提交目标保留，本任务临时内容清理，用户已有结果不变 |
| R06-AC07 | 元数据或条目不受支持 | 按声明规则报告，不以静默丢弃达成表面成功 |
| R06-AC08 | 从整理结果进入压缩任务 | 带入清单可检查，源变化处理明确，不扫描混入历史文件 |

完整转换可用文件路径及内容摘要对照；对于明确的整理转换，使用规则生成的预期清单，不拿原归档总文件数直接判断成功。

## 6. 非目标与阶段出口

不包含原包内编辑、原地替换、修复损坏来源、RAR 创建、自动删除来源或承诺压缩体积必然下降。大规模流式优化、断点恢复和任意图形化管线另行考虑。

阶段出口是普通格式转换、结果打包以及声明范围内的有限复合流程可独立使用。R07 可为这些用例增加经过验证的目标格式，R08 可复用其稳定结果与动作契约。
