# R01：简洁交互与解压体验

> 状态：规划中 · 实施映射：未分配
>
> 前置：当前 V1 解压闭环；详见 G0006 实际结果。
>
> 产出：让已有解压能力以更少的必要操作完成，不增加新归档格式。

## 1. 用户目标与主流程

用户把一个或多个压缩包放入页面，确认输出位置，点击“开始解压”，结束后直接打开结果。需要递归、密码或编码调整时，在相关位置展开。

当前页面同时展示输入列表、处理树、详情和多项配置。本阶段重新分配它们在不同任务状态中的显示优先级，保留批量、递归、候选密码、重试和结果解释能力。

## 2. 交付范围

| 区域 | 目标行为 |
| --- | --- |
| 空状态 | 明显的拖放区域和添加入口；添加文件夹扫描作为次级入口 |
| 待开始 | 默认突出输入摘要、输出目录、开始解压；支持查看和移除输入 |
| 递归 | 提供“继续解压内部压缩包”轻量入口，开启后显示总层数 |
| 密码 | 默认折叠；支持开始前输入，以及失败后在当前会话补密重试 |
| 编码 | 移到更多选项或相关错误的处理入口，保留原有选择能力 |
| 运行中 | 当前项、已完成与失败数量、取消；处理树和明细可展开 |
| 完成后 | 明确的结果摘要和打开结果入口，失败项提供相关操作 |

初次开启递归建议总层数 2，关闭为 1，最大仍为 16。文案必须说明总层数包含外层，不能把原 `MaxDepth` 误译为“额外再解几层”。普通目录和 TAR 组合归档计层规则保持一致。

输入输出建议在当前任务内确定，不建立最近目录或历史任务库。能可靠给出输出建议时必须展示完整可检查位置；多来源等无法可靠确定的情况，由用户选择后开始。

## 3. 关键行为约束

- 默认值可用，不要求先选择编码、配置预算或输入不存在的密码。
- 结果树的折叠不隐藏部分失败和按深度停止的摘要；选中节点后能够查看来源、输出和诊断。
- 缺密不阻断独立其他包；补密在当前批次内复用，不在多个 Document 之间传递。
- 调整编码或源内容等不能使用原重试语义的情况，应明确启动新批次，不能只重新调用 Retry。
- 正在运行时冻结本次参数；清空、重复开始、关闭和迟到事件沿用现有会话约束。
- 运行期间不以连续密码弹窗或自动跳转详情打断用户。

## 4. 工程切入与阶段交付物

重点检查 `UnpackView`、`UnpackDocument`、文件选择与拖放适配、状态绑定和现有 UI 测试。Headless 已有语义是依据，UI 不维护另一套层数和失败判断。

详细执行计划应交付：

1. 五类主要任务状态的布局方案，以及默认／按需控件清单。
2. 输出建议、递归开关、候选密码和重试的精确交互规则。
3. 旧页面操作到新入口的映射，证明核心能力仍可发现。
4. 深浅主题、窄窗口、键盘导航、原生拖放／选择器和 DPI 验证方案。
5. 当前产品使用文档更新，和真实完成的实机检查记录。

## 5. 验收场景

| 编号 | 场景 | 阶段出口要求 |
| --- | --- | --- |
| R01-AC01 | 普通 ZIP，默认操作 | 不打开更多选项即可开始；得到正确的一层输出 |
| R01-AC02 | 一个包包含多个内层分支 | 开启总层数 2，所有允许分支展开，第三层正常停止 |
| R01-AC03 | 同批次普通包与加密包 | 普通包正常完成；加密项补密后可重试，成功内容不重复处理 |
| R01-AC04 | 旧 ZIP 文件名编码不匹配 | 能找到编码处理入口，并明确新批次要求 |
| R01-AC05 | 写入中取消或关闭 | 取消状态与实际退出一致，成功产物保留，未提交内容清理 |
| R01-AC06 | 窄窗口、主题、键盘、DPI | 主要动作可见可达，提示不遮挡，原生检查与自动渲染分别记录 |
| R01-AC07 | 同时打开两个解压任务 | 参数、密码、结果和关闭行为相互隔离 |

内容与结构回归沿用真实样本；纯展示调整不新增镜像实现的测试。新增默认值映射或状态逻辑则覆盖其实际行为。

## 6. 非目标与下一阶段输入

不包含压缩创建、任务历史、Dock Tool、通用布局框架或全仓重命名。真实 Host 发布验收与本阶段原生交互检查分别记录，不以 Standalone 通过替代正式交付。

执行计划需收敛窄窗口布局、输入摘要与详细列表的切换、输出建议算法。推荐优先复用现有控件和状态，不为减少视觉信息引入新任务模型。

交付给 R02 的基础是：稳定的简洁任务页规则、经过验证的生命周期、可复用的必要交互组件，以及仍然完整的解压用例。
