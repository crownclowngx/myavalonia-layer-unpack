# R07：格式扩展与诊断

> 状态：矩阵、检查与 TAR/TAR.GZ 创建已实施；7z 创建验证未通过、继续规划 · 实施映射：[G0013](../refactoring/G0013/result.md)
>
> 前置：R02 创建、R04 浏览；加密和转换扩展分别复用 R03、R06 已完成部分。
>
> 产出：按验证证据增加格式能力，帮助用户理解归档为什么无法处理。

本轮选入前两个实施单元并独立验证 7z 候选。SharpCompress 0.50.4 的混合条目样本未通过插件回读与独立 libarchive 验证，7z 创建未开放，不能将整个 R07 标为完成。详见[G0013 计划](../refactoring/G0013/plan.md)、[实际矩阵](../refactoring/G0013/format-support-matrix.md)和[候选评估](../refactoring/G0013/sevenzip-evaluation.md)。

## 1. 用户目标与优先顺序

用户需要确认一个包能否完整读取，或在 ZIP 之外创建已验证的归档格式。默认日常操作仍使用 ZIP；诊断在用户请求或发生问题时出现。

建议拆成三个实施单元：

1. 统一能力矩阵与按需完整性检查。
2. 根据实际资料交换需求加入 TAR / TAR.GZ 创建。
3. 对 7z 创建进行独立验证，形成明确支持范围后再开放。

后两项按需求选择，不为增加格式数量同时启动所有引擎工作。详细计划明确选入哪些单元，未选部分保持规划中；完成一个单元不代表整个 R07 已完成。

## 2. 能力矩阵与界面规则

| 维度 | 需要分别记录 |
| --- | --- |
| 读取 | 可识别、可枚举、可全部解压、可选择性提取 |
| 创建 | 可创建的容器、压缩方式、大文件／Zip64 和空目录边界 |
| 密码 | 内容加密、头部加密、文件名可见性及实际互操作工具 |
| 校验 | 可检查的长度、CRC、认证信息，以及不能验证的变体 |
| 特殊情况 | 固实、分卷、损坏、编码、链接和元数据支持 |

格式选项只展示当前创建任务实际支持的能力。选择一个格式后，仅出现该格式可用且有用户意义的选项；不可用原因简短说明，不展示需要用户自行拼配的大量底层参数。

创建和读取矩阵分别维护，再提供面向用户的简短说明。复杂引擎细节放在文档和诊断详情，不进入默认任务页。

## 3. 技术判断基线与重新验证

当前仓库锁定 SharpCompress 0.50.4、SharpZipLib 1.4.2。2026-09-07 讨论时核对的官方资料表明：

- SharpZipLib 提供 ZIP 写入接口，可作为已有依赖的创建候选。[ZipOutputStream 文档](https://icsharpcode.github.io/SharpZipLib/help/api/ICSharpCode.SharpZipLib.Zip.ZipOutputStream.html)
- SharpCompress 0.50.4 列出 TAR / TAR.GZip 写入和 7z 非固实 LZMA / LZMA2 写入；7z 输出需要可定位流。RAR 无 Writer 支持。[0.50.4 格式矩阵](https://github.com/adamhathcock/sharpcompress/blob/0.50.4/docs/FORMATS.md)

以上只证明候选库提供相关接口，不代表本插件已经支持创建，不证明加密、固实写入或任意变体均可用。开工时核对当时锁定版本的实际 API、许可、资产和真实样本；不以主分支新文档替代锁定版本证据。

优先使用现有运行时与依赖。若目标能力要求新库或外部进程，在详细计划中单独评估发布资产、取消、诊断与维护成本；不预设需要更换全部引擎。

## 4. 检查与诊断语义

“检查压缩包”需区分仅读取目录和完整内容检查。能够列目录不能直接显示为内容完整；检查结果说明实际读取范围、通过的验证、受限项目和失败原因。

完整检查可能需要读取全部内容和密码，并消耗相应资源。检查用例可不在用户目标目录输出文件，但解码过程仍受预算、取消与临时空间管理约束。

重点诊断包括：缺少可用密码、格式或加密变体不支持、缺卷、内容损坏、编码问题、来源不可用和资源上限。引擎无法区分密码错误与损坏时保留歧义，提供可尝试的下一步，不编造确定原因。

RAR5 加密 MAC 等既有限制继续进入结果。任何“已验证”标签都必须对应实际执行的校验类型，不能借格式扩展消除仍然存在的限制。

## 5. 阶段交付物与验收

交付物包括：按操作区分的支持矩阵、每项新能力的真实夹具和摘要、独立工具互操作记录、统一诊断契约、检查任务交互、性能与取消数据，以及必要的依赖资产更新。

| 编号 | 场景 | 阶段出口要求 |
| --- | --- | --- |
| R07-AC01 | 读取支持多于创建支持 | 创建页面只提供已验证可写格式，用户文档区分能力 |
| R07-AC02 | 新格式正常创建 | 文件、目录和内容正确，独立工具可读取，限制明确 |
| R07-AC03 | 新格式不支持某密码或压缩模式 | 界面不提供无效组合，Headless 也明确拒绝 |
| R07-AC04 | 可列目录但内容截断或损坏 | 完整检查发现异常，不用目录成功冒充内容通过 |
| R07-AC05 | 密码错误、缺卷、编码问题 | 可确定时给出准确类型，不可确定时保留歧义与下一步 |
| R07-AC06 | 校验受限格式 | 正常读取与未完成认证分别展示 |
| R07-AC07 | 大包或大量条目检查中取消 | 可观察退出，资源与临时清理有实测证据 |
| R07-AC08 | 默认 ZIP 与已有解压回归 | 新格式不增加普通任务必填项，不破坏既有已验证行为 |

## 6. 非目标与收缩规则

不包含 RAR 创建、自动修复损坏包、通用分卷拼接、全格式承诺、引擎参数控制台或自定义压缩算法。分卷需求可以单独立项，不因诊断出缺卷就宣称能够拼接。

某个格式验证失败时保留当前已验证能力，记录未通过变体、原因和后续归属。若选择收缩阶段范围，更新路线图与详细计划，不能把未实现格式记为验收通过。
