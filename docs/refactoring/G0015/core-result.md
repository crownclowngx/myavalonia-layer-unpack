# G0015 核心实现记录（01–04、06）

日期：2026-09-19。核心阶段已实现并验证；完整 UI 与统一本地门禁以 [result.md](result.md) 为准。

`ArchiveSource` 只保存不可变来源，`ArchiveSourceResolver` 负责同目录标准数字卷归组，`ArchiveSourceReader` 负责流所有权、预算及来源核对。`IArchiveExtractor` 改为接收逻辑来源，具体引擎的字符串便利重载也委托相同解析器。没有增加策略注册器或外部运行时程序。

顶层可选择任意卷，内层仅使用父提交清单；新增邻近卷不会被旧节点接管。组内检查数字排序、缺首卷／中间卷、重复编号、零号和补零歧义。默认 256 卷，上限可配置但不超过 1024；4 GiB 输入预算按整组累计，2 GiB 单文件、10 GiB 总展开等原预算不变。

所有输入文件句柄都采用共享读；会话租约覆盖密码尝试，引擎每次尝试借用自己的受控流租约。最多约 `2 × 卷数 + 1` 个来源句柄（尚不含输出文件），每流 4 KiB 缓冲，失败或取消统一释放。成功提交前重新按路径打开核对摘要；第一次读取和重试摘要包括序号、路径、长度、修改时间以及每卷 SHA-256。不承诺跨平台全局原子文件系统快照。

7z 使用 SharpCompress 0.50.4 的显式有序流 API；探测窗口可跨卷，没有合并临时归档。读取器里的同步 Read/Seek 也检查操作取消。独立夹具覆盖固实、非固实、LZMA/LZMA2、AES 内容／头加密、中文、空文件和空目录。测试发现该版本对没有 Folder 的空文件误报 IsEncrypted：适配层排除 7z 的零长度正文，加密头和有正文的条目仍由引擎验证。[上游对应实现](https://github.com/adamhathcock/sharpcompress/blob/0.50.4/src/SharpCompress/Common/SevenZip/SevenZipFilePart.cs)

调度改为最浅层分桶、层内串行、层完成后统一发现。混合深度重试将新第三层放在既有第四层前；预算和成功节点身份保持。父提交后发现失败只附加诊断；深度停止仅建立逻辑节点，不跑密码或读取正文。

检查、普通转换、展开整理转换和 Workflow 复用来源模型。整理验证一个内层组的所有成员都来自父清单；原卷与后代内容仍归最外层来源，不额外分裂整理来源。公开 Workflow v1 Schema、动作和 Document 身份保持。
