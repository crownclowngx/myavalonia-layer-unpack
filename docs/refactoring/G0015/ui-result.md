# G0015 界面与恢复路径实现记录（05–06）

日期：2026-09-19。沿用三个 Document 和现有两个 Workflow 动作身份，新增功能通过解压页现有入口使用。

输入发现返回逻辑来源快照。添加首卷、续卷、全部卷或扫描同一目录，界面都只显示一行组名和卷数；路径及发现诊断放在折叠详情中。开始时复核已展示成员，变化则给出 InputChanged，用户重新识别后再开始。发现和会话准备移到后台，关闭后的结果不能回写页面。

缺卷补齐后，选择失败节点点击“重新识别此组…”。复用临时子页所有权容器，创建独立 UnpackDocument，带入来源、原批次编码和输出位置，剩余层数为 `max(1, 原总层数 - 节点深度 + 1)`。该值依据真正执行过的批次，不依据用户事后编辑的选项。新页不复制密码、不自动解压，返回后原父包结果和失败事实仍可检查；关闭父页会取消并排空子任务。

修正了显式内层输入与扫描输出排除的冲突：扫描目录仍排除已有输出，用户主动选中的包或卷可以位于已成功父目录内。因此重新识别只处理该组，不必重做成功外层。

独立完整检查、普通／展开转换和结果打包仍通过各自上下文任务处理，密码和取消不跨任务共享。分卷成功不扩张 7z 浏览能力，也不改变 Workflow v1 封闭 JSON。

阶段验证：Plugin **137/137**，零失败、零跳过；阶段当时新增 5 个界面／生命周期用例和 3 个分卷 Workflow 用例；收尾再补真实 Drop 路由事件用例，最终 Plugin 为 138 项。TRX：`artifacts/G0015/stage-ui/g0015-ui.trx`。后续全量门禁的实际数量以 [result.md](result.md) 为准。
