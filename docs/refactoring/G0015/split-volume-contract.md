# G0015 分卷识别、读取与恢复契约

日期：2026-09-19。状态：**已实现契约，最终本地证据见 [结果](result.md)**。适用于本期标准 7z 数字分段；不能将此契约解释为所有格式的通用多卷支持。

## 1. 一个逻辑来源

逻辑来源包含：来源种类、代表路径、显示名、有序物理成员、来源范围和诊断。读取开始后另持有每卷长度、时间和 SHA-256；对外集合只读并复制输入，不公开库对象、文件句柄或密码。

单卷是只有一个物理成员的逻辑来源。7z 分卷组是同目录中 `名称.7z.001` 起始的一组文件。多个成员不产生多个业务节点；尝试次数、超时和事务属于整组。一个包内解出三个分卷时，三个物理文件仍各自计入父包已写字节和条目账本。

## 2. 名称、范围和去重

| 项目 | 约定 |
| --- | --- |
| 标准名称 | 本期首先支持 `.7z.001` 起始、至少三位 ASCII 数字后缀；大小写按平台路径政策处理 |
| 编号 | 按数值排序，不用字符串排序；必须有第 1 卷，不允许零号、重复数值或不明确的补零混用 |
| 分组键 | 规范父目录＋去掉数字卷后缀的基础名称；内层还受同一次父包提交范围约束 |
| 任意卷输入 | 直接选择 `.002` 时在同目录受限枚举相同基础名称成员，定位首卷；缺首卷形成可见诊断 |
| 重复输入 | 多选首卷、其他卷、目录扫描结果时只保留一个逻辑任务；稳定顺序以最先加入该组的位置为准 |
| 内层发现 | 只使用父包提交时的普通文件清单，按各自直接父目录归组，不接纳历史文件或后来创建的文件 |
| 单卷名称冲突 | 同目录同时存在 `项目.7z` 和 `项目.7z.001` 时是两个来源，不合并；输出按现有不覆盖编号策略分配 |
| 非标准名称 | `.7z001`、裸 `.001`、RAR／ZIP 分卷等不靠猜测收录；给出本期范围说明，不静默重命名 |
| 链接和路径 | 沿用已有链接、重解析点、特殊文件及越界政策；引擎不能越过解析出的成员清单找卷 |

先收集候选并归组，再探测逻辑包格式；不能先因 `.002` 没有归档签名而把它丢弃，也不能对每一卷都要求 7z 开始签名。只有续卷没有首卷时仍保留“缺首卷”的任务，不把该组静默过滤为普通文件。

GUI 预览只读。开始时重新核对已展示的成员清单；若成员变化，报告 InputChanged 并提供显式重新识别入口，普通未变化组不增加确认。Headless 无预览调用在创建会话时解析并冻结，执行期间不重新扫描接纳新成员。

## 3. 连续编号与完整性

发现 `.001`、`.003` 可确定缺少 `.002`。只有 `.001`、`.002` 时不能只按编号推断总共只有两卷；“最后一卷缺失”和“末尾损坏”可能无法区分。

对可靠且通过头校验的格式信息，可交给引擎结合总长度验证。最终以已声明的完整解码、条目长度和 CRC 等实际证据判断成功。不能强制假定除最后卷以外均等长，不以最后卷较小作为唯一结束证据，不修改数据来伪造完整性。

| 情况 | 诊断与动作 |
| --- | --- |
| 缺首卷／中间编号缺口 | MissingVolume，列出可确定的缺失卷名；不进入密码循环 |
| 缺末卷或截断，无法区分 | 保留 MissingVolumeOrCorruptArchive 歧义；不编造“缺第 N 卷” |
| 编号重复、来源清单有歧义 | 明确的来源校验诊断，要求整理输入；不任意选择某个文件 |
| 密码不正确或加密内容损坏 | 复用密码／损坏歧义，补密时重新验证整组来源 |
| 任一成员新增、删除、替换或内容改变 | InputChanged；当前执行失败或旧重试失效，不继续使用一部分新、一部分旧输入 |
| 访问受限、输出错误、预算或超时 | 复用当前领域诊断，保留原组和已成功输出 |

对没有明确证据的错误不强行区分损坏与缺卷。用户信息采用简短中文和下一步，不暴露原始引擎异常链、密码或堆栈。

## 4. 联合读取与来源一致性

在进入提取前验证所有成员的路径、数量和总字节。对实际参与的所有卷持有受限只读句柄，在 Windows 上禁止同时写入／删除当前持有文件；所有权属于该次读取操作，释放覆盖成功、异常、超时、取消和准备部分失败。

形成路径、卷序、长度、时间及 SHA-256 的成员快照。对每次新尝试／补密重试核对整组，不能只比较首卷。摘要也可读取相同受控句柄，随后恢复正确位置，不能误将摘要后的末尾位置交给引擎。

非 Windows 文件系统或外部并发修改的保证必须按实际平台记录；提交前进行适用的来源复验，但不宣称跨文件全局原子快照。变动检测覆盖同长度同时间戳的正文替换，以及中途卷丢失／不可读。

引擎接收明确有序的成员或可定位逻辑流。默认不落盘完整合并文件、不将整组装入内存；句柄数、缓冲区和元数据都有有限上界。若锁定库在解码内部仅支持协作取消，记录实测退出时间，不承诺硬中断。

## 5. 资源计量

| 限制 | 本期规则 |
| --- | --- |
| 单逻辑来源输入 | 所有卷长度之和不超过 MaxInputBytes，默认仍为 4 GiB |
| 单组卷数 | 有限上限，默认 256、可配置最高 1024；超过时明确失败，不截断成员清单后尝试解码 |
| 来源发现 | 保留 100,000 项扫描上界；显式输入也不能绕过扫描和卷数约束 |
| 归档节点数 | 逻辑组计 1，默认批次 MaxArchives 仍为 1,000；Workflow 保留自身更小的入口限制 |
| 展开量 | 单文件默认 2 GiB，批次累计默认 10 GiB，目录／条目上界沿用；所有层和失败尝试不退款 |
| 时间 | 执行时来源核对、摘要、引擎读取和提交共用本逻辑包的 5 分钟默认超时；每卷不得重新计时 |
| 取消 | GUI 只读发现、摘要、跨卷读取、输出写入、收尾和关闭排空均传递令牌 |

用户尚未确认典型卷组体量；此次方案不提高现有输入和展开默认值。实现必须把“组总量超限”与“缺卷”区分，并能在受支持的 Headless 参数范围内验证更高预算，而不把它当作默认支持声明。

源长度上限不等于读取 I/O 总量：摘要、引擎 seek、补密可能重复读取。记录整组源字节、实际展开字节、准备／解码耗时及适用的资源数据，不把摘要字节错误计为展开产物；如需要独立读取总量限制，须给出统一契约和测试，不能藏在 UI。

## 6. 输出与深度

一组一个 OutputTransaction。`项目.7z.001` 的建议输出名为 `项目`，不能残留 `.7z` 或 `.001`；组与普通包输出同名时按现有编号规则不覆盖。

所有需要的条目完整解码并完成校验、来源复验后才提交。某个卷失败不提交“前几卷成功目录”；清理本组暂存并保留准确残留位置。已提交外层、成功兄弟、原始卷文件始终保留。

只读组装本身不增加归档层级。若最大深度为 1，外层解出组文件后只创建一个第二层 DepthLimit 节点，不打开组正文、不跑密码、不为每卷分别创建停止节点。名称归组、有限文件元数据与已有受限签名探测不能升级为目录解码或全组摘要。

## 7. 重试与重新识别

卷清单和摘要不变时，密码／可恢复访问问题可沿用原节点重试，预算继续累计，成功父包和兄弟不重做。

补卷、删卷或替换成员属于新输入；旧结果维持原诊断。本期“重新识别此组”带入新的同类型解压任务，使用当前实际分卷目录，重新解析、显示名称和输出建议，用户显式开始。新任务从该组作为第一层处理，剩余总层数建议取 `max(1, 原总层数 - 原节点深度 + 1)`，并可见地展示，不能悄悄增加展开深度。

该入口不自动重跑父包、不覆盖旧产物、不继承密码。新任务拥有独立预算，这是明确的新操作而非伪装为同会话退款；旧会话补密 Retry 仍共享原账本。后续若需要原会话的卷组替换，应另立契约，不能直接放开现有 CanRetry。

## 8. 文档与能力声明

实施通过后分别更新“可识别、可全部解压、可完整检查、可转换”范围；7z 浏览、选择提取、创建能力不因此改变。卷组成功不扩大 RAR5 等其他格式认证承诺。

本契约的实测状态应在[验收矩阵](acceptance-matrix.md)和[结果](result.md)记录。当前只有方案，全部功能证据待执行。
