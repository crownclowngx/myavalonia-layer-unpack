# G0015 按层调度、重试与取消设计

日期：2026-09-19。状态：**已实施并有实际顺序回归**，最终门禁见 [结果](result.md)。本方案已替换 UnpackSession 调度顺序；[G0004](../G0004/recursive-execution-design.md)继续描述历史深度优先实现，不改写旧证据。

## 1. 层级与执行单位

顶层逻辑来源为第 1 层，普通目录不计层，分卷组整体计 1 层。TAR.GZ／TAR.BZ2／TAR.XZ 的组合规则不变；GZip 解出 ZIP 则 ZIP 为下一层。

一个逻辑包完整提交后才可能发现其后代。广度优先的新增约束是：当前层的其他包也必须结束，下一层才开始解码。包内条目按引擎要求读取，固实包的流式顺序不改变。

例如根包 A、B，A 内有 A1 和 A2，A1 内有 A11，B 内有 B1：

```text
现有 DFS：A → A1 → A11 → A2 → B → B1
目标层序：A → B → A1 → A2 → B1 → A11
```

同层使用确定顺序：根按请求中的首个逻辑来源位置；下一层按父节点执行顺序、父提交清单相对路径的稳定排序，卷成员按数字排序但不增加调度节点。GUI 自身可能已排序输入，服务遵循实际请求顺序。

## 2. 两个有限队列即可

将现有 ExecuteNodeAsync 中“提取当前包”和“递归执行孩子”分开。包提取方法只返回已提交结果及可用于发现的有限清单，不能在内部调用后代执行。

```text
当前层 = 已归组的顶层来源
while 当前层不为空:
    逐个执行本层节点，完整处理成功、失败或取消
    若批次必须停止：结束调度
    从本层成功节点的提交清单中归组并建立下一层节点
    对超过最大深度的节点记录 DepthLimit，不启动解码
    当前层 = 尚可执行的下一层节点
```

下一层仅来自本次成功的父清单。不得全盘扫描输出根，不接管历史结果，也不接纳其他会话随后写入的文件。组只在一个父包的提交清单与相同直接父目录内形成；层屏障不意味着允许跨父目录拼接同名卷。

分配节点、构建队列前扣发现／节点预算，队列上界受 MaxArchives 和发现限制约束。不能先无限收集再检查数量。发现预算耗尽按现有批次停止语义记录，不创建指向父包自身的假失败节点。

## 3. 层结束与失败

| 情况 | 调度结果 |
| --- | --- |
| 当前包成功 | 独立提交，立即可在结果中看到；后代等待本层结束 |
| 缺卷、缺密、普通内容损坏 | 本逻辑包失败，本层其他独立包继续；不为失败包发现后代 |
| 同层既有成功也有失败 | 普通失败不阻止成功父包的下一层；批次最终汇总为部分失败 |
| 缺卷尚未补齐 | 明确失败，不轮询文件系统，不让层屏障无限等待 |
| 预算、安全路径等批次停止故障 | 停止后续层与当前层剩余节点，保留已成功提交 |
| 成功父包的发现出错 | 保留父包 Extracted，附加发现诊断与 DiscoveryFailures；不能把完整父产物伪装成提取失败 |

层屏障只限制开始顺序，不形成整层事务；一项失败不会回滚本层其他成功目录。下层失败也不会改写父包已成功提交的事实。

## 4. 密码池与超时

当前会话仍共享有限密码候选池。每包依次尝试无密码、已命中候选和其他候选；DFS 改 BFS 后命中顺序可能变化，因此耗时和预算触发点可能变化，不能承诺与历史尝试次序完全相同。

同一组的多个卷属于一次逻辑来源，不分别轮询密码。单包超时覆盖该组准备、提取及提交，不传递给所有后代；批次取消令牌继续覆盖全部层。发现阶段单独检查取消和有限扫描预算，不借父包已释放的超时令牌无限工作。

## 5. 原会话重试

Retry 仍只接受当前会话可恢复的失败节点，先验证所有请求 ID、清理状态与成员摘要，再运行；不重复成功节点或重新解成功外层。

选中不同深度的失败节点时，按节点原始 Depth 非递减执行。为每个深度使用一个有限桶：同深度按原节点顺序处理；该层新发现的孩子追加到下一深度桶，已存在且选中的节点优先保持原顺序。维护节点／逻辑来源去重，避免同一节点执行两次。

不能将混合深度的重试节点简单放到一个 FIFO 队列末尾就声称 BFS；例如第 2 层节点重试后新发现第 3 层包，应先于原先选中的第 4 层失败节点执行。

所有尝试继续消耗原 ExecutionBudget。旧卷组补齐后进入[重新识别的新任务](split-volume-contract.md)，不混进原会话重试队列，避免旧深度、成员和摘要失效。

## 6. 取消与关闭

用户取消覆盖正在准备、读取或清理的当前组，排空真实工作后才结束；当前组未提交部分回滚。已提交节点保留成功，已知未执行节点按现有取消／未执行规则收口。未发现的后代没有虚构的取消节点，摘要不能声称统计了全部未知后代。

Document 关闭继续等待不依赖 UI 线程的后台任务和所有卷流释放；迟到进度不能修改关闭页、新批次或另一任务。操作代次和取消状态在同一呈现边界管理，不将 UI 控件传入调度器。

## 7. 共享用例的边界

解压 GUI、Headless、无密码 Workflow 的单个解压会话使用同一层序。普通转换 discoverChildren=false 时不发现后代；展开整理转换在每个独立来源会话内按层，不改变 RepackService 原有逐来源输出与总体预算契约。

节点 Id／ParentId 继续承载树关系，列表插入顺序可以改变；UI、整理、转换和 JSON 投影不得依赖“相邻节点必为父子”或旧 DFS 索引。进度显示当前层与已发现任务，不能提前假定整个树的总任务量。

## 8. 必要顺序证据

调度测试记录引擎实际开始／退出事件，验证 `A、B、A1、A2、B1、A11` 等顺序及前一层全部结束后下一层才开始；不能只断言最终 Nodes 列表按深度排序。

同时验证慢同层包、普通同层失败、发现阶段取消、深度边界、混合深度重试和源变化。真实格式样本负责内容完整性，控制型提取替身只验证调度与故障时序。全部场景见[验收矩阵](acceptance-matrix.md)。
