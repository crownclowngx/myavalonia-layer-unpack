# G0011 / R05 计划：输出整理

日期：2026-09-08。对应 [R05](../../roadmap/R05-output-organization.md)。按用户要求实现文档内容，沿用 G 编号档案，不使用 AIFLOW、Windows CI 或发布门禁。

## 范围与顺序

1. 在解压暂存提交边界补充明确的文件与目录清单，包含文件内容凭据；不从历史输出根补清单。
2. 新增独立 Headless 整理规划与执行用例：有限扩展名筛选、顶层来源归属、单子目录包装链、稳定命名、可检查映射。
3. 实现来源复验、普通复制、独立暂存和精确不覆盖提交；取消与失败只清理本次未提交内容。
4. 从解压结果进入临时整理子任务，支持预览摘要、分页详情、错误与成功目录入口；明确返回、新批次、重试、清空及关闭责任。
5. 真实 ZIP 复杂样本、摘要与目录清单、变化/冲突/预算/链接/失败/取消/并发测试，页面与 Scope 测试，资源测量及完整本地 Debug 门禁。

## 设计约束

SOLID 优先。解压只提供结果契约；整理规划负责规则和映射，执行负责事务，复制适配器负责流；页面依赖窄用例接口。朴素使用不可变计划、适配器和事务，不增加通用工作流或文件管理框架。中文注释说明设计原因、所有权和边界。

本期输入仅来自当前 `UnpackResult`。浏览页中“全部解压”进入的真实解压子任务自然获得相同整理能力；不扩展 `BrowseExtractResult` 为另一套整理输入。默认全文件、按来源、不开启压平；其他类型按扩展名明确选择。

## 完成标准

R05-AC01–08 的“提交清单 → 预览映射 → 独立整理目录”闭环有实际证据。完整本地门禁覆盖锁定还原、Debug 零警告构建、引用资产求值、两项目全量测试且零跳过、格式、文档路径及差异空白检查。原生交互、DPI、真实 Host 与发布检查没有执行时必须列为遗留。
