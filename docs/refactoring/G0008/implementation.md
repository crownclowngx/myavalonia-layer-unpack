# G0008 实施方案：基础 ZIP 创建

日期：2026-09-07。对应 R02，实施工作项见[计划](plan.md)，实际验证见[结果](result.md)。

## 职责与设计理由

| 组成 | 职责 | 取舍 |
| --- | --- | --- |
| PackRequest / PackPlan / PackResult | 冻结请求、可检查清单、结果 | 不暴露任意格式或密码字段；清单构造仅对规划器开放 |
| PackPlanner | 输入规范化、去重、根名、枚举、内容摘要、来源复验 | 只读准备，不因用户查看清单创建输出目录 |
| IPackService / PackService | 准备与执行用例、超时和错误转换 | 每次调用局部状态，可同时服务独立任务 |
| IArchiveWriter / ZipArchiveWriter | 将确定清单写为一个 ZIP 并完成收尾 | 新增窄写入端口，解压接口保持原职责 |
| PackOutputStream | 在真实写入处限制输出长度与检查取消 | 按最大文件位置计量，头部回填不重复计费 |
| PackFileTransaction | 排他创建自有暂存文件、不覆盖移动提交、回滚 | 不借用解压的目录事务，不递归清理用户目录 |
| PathPolicy / PackPaths | 共享名称和链接政策，转换领域错误 | 抽出纯名称规范化，创建无需虚构一个落盘目录来验证名称 |
| PackDocument | 用户参数、清单摘要、命令、进度和关闭 | Headless 处理文件，页面只处理用户意图与展示 |
| PackView | 选择器、拖放、打开产物目录 | 异步选择器返回时核对原 Document 仍可编辑 |
| MainWindow / StandaloneServices | 两页真实预览，各自 Scope | 标签切换不取消任务；关闭同时取消两类生命周期并排空 |

S：规划、归档写入、提交与呈现分责。O：创建格式的变化留在写入适配和未来明确契约中，不在解压会话加模式分支。L：写入替身遵守流所有权、取消和不提交规则。I：两项创建用例与一个单包写入端口；没有通用归档上下文。D：Document 依赖 IPackService，编排依赖 IArchiveWriter；具体规划器是单一稳定策略，不为每个工具类增加接口。

## 执行数据流

选择输入 → 只读准备及摘要 → 展示输入到包内根名称 → 校验来源 → 暂存 ZIP → 写入时摘要复验 → 归档收尾 → 来源清单复验 → 不覆盖提交 → 返回实际产物。

`.NET 10 ZipArchive` 的异步创建与条目流作为写入引擎，保持现有 NuGet 锁定版本和插件私有资产不变。SharpZipLib 用于测试中的独立目录、内容与 CRC 校验，现有解压用例用于端到端回读。

## 关键选择

- 准备读取一次源内容、压缩再读取一次，以摘要捕获长度和时间戳被保留的内容变更。性能代价如实记录，不承诺文件系统原子快照。
- 压缩目标位于已有源目录内时，精确排除请求目标及本次临时文件。源内不存在的新输出子目录在准备时提示改选或预先创建；不会把新目录悄悄加入包内。
- 同名根确定编号，父目录覆盖已选子项。没有事先显示过的重要映射变化时，首次开始只准备并展示清单，用户再次开始执行；普通添加已完成准备不增加步骤。
- 当前普通 ZIP 使用标准 Deflate、UTF-8、无加密；创建矩阵与解压矩阵分开。支持的文件系统元数据范围见[创建契约](creation-contract.md)。
- 全部合成一个包是一个提交单元。失败不产生“部分成功 ZIP”；成功文件不会被清空任务删除。

## 生命周期

后台工作仅捕获冻结参数、清单和令牌。关闭取消并等待不依赖 UI 的工作任务，避免 Host 同步 Scope 释放与 UI 续体互相等待。UI 代次和关闭标记拦截迟到进度；取消完成后才解除忙碌状态。

新增 Document ID 为 `myavalonia.plugin.layer.unpack.document.pack`，已有 Plugin / 解压 Document ID 不变。Standalone 显示名为“压缩包工作台 / Archive Workbench”，工程名称与程序集未重命名。无新增 Tool、Workflow、全局命令或历史持久化。
