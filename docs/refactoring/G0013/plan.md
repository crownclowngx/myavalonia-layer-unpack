# G0013 / R07：格式能力与按需诊断

日期：2026-09-09。基线提交：`366c5d6af2cc7a1bf436777338df45a46fc138e1`。

本轮实现用户指定的 [R07](../../roadmap/R07-format-support-and-diagnostics.md)，遵守 SOLID、朴素模式、详细中文注释、单元测试和本地门禁；不使用 AIFLOW、Windows CI 或发布门禁。

## 选入的实施单元

1. 统一读取／创建能力矩阵、诊断与下一步建议，提供目录检查和完整内容检查。
2. 普通创建增加 TAR、TAR.GZ；沿用清单、来源验证、预算、批次和事务。
3. 独立验证锁定 SharpCompress 0.50.4 的 7z 非固实 LZMA2 写入。只有真实文件／空文件／目录／空目录／中文与独立工具互操作全部通过，才开放产品入口。

第三单元验证出现真实失败，按 R07 收缩规则停止产品接入：压缩头、普通头两类混合条目样本均被独立 libarchive 拒绝。保留候选评估、夹具及拒绝测试，7z 创建继续规划中，不能把 G0013 完成等同于整个 R07 完成。详见[候选评估](sevenzip-evaluation.md)。

## 实现边界

不新增依赖或生产外部进程。TAR 使用 .NET 10 `System.Formats.Tar` 的 PAX Writer，TAR.GZ 外包 `GZipStream`；ZIP 仍沿用运行时／SharpZipLib 原实现。SharpCompress 0.50.4、SharpZipLib 1.4.2 锁定及许可证资产不变。

检查仅处理当前逻辑归档，不递归内嵌包；目录检查仅 ZIP。正文可使用私有临时目录，受累计展开预算约束，成功也回滚。返回精确验证证据、限制、取消状态和清理残留，不输出用户产物。

转换和提交清单重新打包的目标仍为 ZIP，并在 Headless 显式拒绝其他目标；普通创建的新格式不自动扩大 R06 已承诺的回读范围。

## 完成标准

真实格式、错误密码、AES/CRC、截断、缺卷歧义、编码、来源不可用、资源预算、取消、超时及清理残留均有测试；新创建格式必须逐项核对相对路径、空目录与正文 SHA-256。默认 ZIP、解压和 R01–R06 测试全部保留。

两个测试项目非零、全通过且无跳过；locked restore、Debug 零警告构建、Debug 资产、格式、独立互操作、Markdown 路径及 diff 检查通过。自动渲染与键盘验证不能代替原生对话框、DPI 或发布验收。
