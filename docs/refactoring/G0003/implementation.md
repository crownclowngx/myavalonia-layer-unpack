# G0003 实施方案：多格式与密码池

日期：2026-09-07。本文描述最终方案；历史模板和中途方案不作为现行实现。

## 最终行为

实现 ZIP、7z、RAR4/5、UTF-8 TAR 与 GZip/BZip2/XZ。PasswordPool 规范化候选并优先复用命中；旧 ZIP 编码按请求隔离。上游和自有夹具具备来源与摘要。

## 职责与设计理由

候选池不认识格式；解码器只处理当前候选。一次失败清理独立临时目录，下一候选不会继承部分文件；错误映射保留密码/损坏的歧义。

公共参数和错误以[执行契约](../G0002/execution-contract.md)为准，不能在 UI 再定义一套深度、密码或重试规则。状态只保留在当前会话；生命周期结束释放密码引用和活动工作。

## 验证方法

FormatTests、GeneratedFormatTests、DiscoveryAndEdgeTests、IntegrityTests 验证真实内容、错误候选、缺卷、混合 AES、名称和长路径。 整仓门禁通过统一脚本执行，命令、环境及数量见[G0006 结果](../G0006/result.md)，避免每个阶段复制一份易过时的测试统计。

## 范围与遗留

RAR5 加密内容缺少 MAC 验证并显示警告；旧编码 TAR 明确失败。超大 ZIP64、全算法覆盖等不作实测通过声明。
