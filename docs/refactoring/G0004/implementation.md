# G0004 实施方案：深度递归与输出闭环

日期：2026-09-07。本文描述最终方案；历史模板和中途方案不作为现行实现。

## 最终行为

实现串行深度优先调度、父子节点、DepthLimit、TAR 组合一层、共享账本和同会话补密重试。摘要拒绝变化源文件，已提交父包与后代失败分开表示。

## 职责与设计理由

只有成功提交后的本次文件清单进入发现，不扫描输出根。每分支计算深度；结果中保留发现中断，不生成指向自身源文件的假子节点。重试资格由核心结果规则定义。

公共参数和错误以[执行契约](../G0002/execution-contract.md)为准，不能在 UI 再定义一套深度、密码或重试规则。状态只保留在当前会话；生命周期结束释放密码引用和活动工作。

## 验证方法

RecursiveTests、LifecycleTests 和 PerformanceTests 覆盖 1/2/3/16 层、多分支、跨格式 A/B/C、源变更、累计预算、并发会话和取消。 整仓门禁通过统一脚本执行，命令、环境及数量见[G0006 结果](../G0006/result.md)，避免每个阶段复制一份易过时的测试统计。
