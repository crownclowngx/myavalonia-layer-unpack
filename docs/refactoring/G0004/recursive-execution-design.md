# G0004 递归、输出与重试设计

## 调度顺序

输入清单按用户加入顺序处理；一个包提交后，按文件相对路径排序发现所有归档子节点，再以深度优先顺序执行各分支。一个会话只有一条执行链，减少共享状态与磁盘争用。独立会话可以并发，输出提交负责碰撞仲裁。

顶层深度为 1，子归档为父 +1，普通目录不增加深度。先比较深度再进入引擎和密码循环。深度 2 的外层可以解开任意数量的第二层分支；第三层节点显示 DepthLimit，源包保留。

压缩流解出 TAR 后在当前事务内继续展开，逻辑层级不增加，但中间文件与最终条目都计入预算。压缩流解出 ZIP/7z/RAR 则先提交，再按下一层发现和调度。

## 单包事务与成功事实

每个候选有新的 `.layer-unpack-*` 临时目录。失败先清理，清理失败停止本节点的后续候选。成功用 Directory.Move 提交为独立包名目录；目标已存在则改用编号，永不合并已有目录。

父包提交之后才发现后代，后代失败不能把父包变为失败。发现过程中预算不足或输入不可读时，在已提交父节点保留 Error 并增加发现中断计数；批次进入 PartialFailure。不会生成可再次解压父源文件的虚假子节点。

源压缩包以及外层解出的内层压缩包全部保留。只处理引擎返回的本次输出文件清单，不扫描输出根、不重复接管以前的产物。

## 密码与预算

所有顶层和后代共用会话内的 PasswordPool；每轮按无密码、命中历史、其余候选尝试，命中历史只存在本批次。各格式引擎只收到一个当前候选，不负责交互或生成密码。

字节、条目、节点和尝试计数属于同一 ExecutionBudget；跨层、换候选、回滚或 Retry 都不会重置。预算故障和不安全路径停止批次，后续 Queued 变为 NotRun，RetryBlocked 为 true。

## 显式重试

Retry 接收当前会话的节点 ID 和追加候选，验证节点可恢复且没有未清理输出。先验证整个追加密码集合再更新，避免非法追加造成半更新。

源文件内容用 SHA-256 与首轮对照；Windows 提取期间持有不允许写入/删除的共享读句柄。内容变化则 InputChanged，需要新批次；源未变化时沿用节点 ID、深度、输出位置和账本，只处理失败节点与它新发现的后代，不重复成功兄弟或父节点。

## 取消与证据

会话关闭令牌、用户令牌和单包超时分别衔接。取消当前包时等待流退出并回滚，之前提交的包保留；单包超时记录 Timeout，独立下一包可以继续。多个 Dispose 调用等待同一个关闭任务。

`RecursiveTests` 覆盖 1/2/3 层、多分支、跨格式 A/B/C、TAR 组合与 GZip 包 ZIP、发现节点预算；`LifecycleTests` 覆盖取消、并发操作、重试摘要、账本与会话隔离；`PerformanceTests` 验证 16 层上限。详见[执行契约](../G0002/execution-contract.md)和[验收矩阵](../G0006/acceptance-matrix.md)。
