# G0007：R01 简洁交互与解压体验执行计划

日期：2026-09-07。状态：实现及本地验证完成，部分原生交互待验收。对应 [R01](../../roadmap/R01-simple-unpack-experience.md)。基线提交：`8ae2949`。

## 目标与范围

保留单一解压 Document、现有 Headless 语义与插件身份，让普通任务通过添加输入、确认输出、开始得到产物。提供明显的空状态，按需展开输入清单、候选密码、编码设置与完整结果树。失败摘要和成功产物入口始终可发现。

本轮遵循 SOLID、朴素模式、详细中文注释、真实业务与界面测试及本地门禁。只执行 Debug、本地测试、渲染和可用的原生交互验证；不使用 AIFLOW、Windows CI、Release、正式 ZIP、部署或发布门禁。不增加压缩、历史、Tool 或 Workflow。

## 已确定交互规则

- 单列可滚动内容配固定底部操作区，Standalone 最小窗口由 1000×600 调整为可用的 640×520。
- 初始默认一层；开启“继续解压内部压缩包”初次取总层数 2，关闭为 1，再开启保留本任务此前有效层数；总层数仍不超过 16。
- 全部输入的直接父目录相同时建议 `<父目录>/解压结果`；空输入或多直接父目录不推导公共祖先。建议不创建目录，用户点击开始后由 Headless 验证和写入。
- 显式编辑输出位置后不再自动覆盖；清空批次解除手动选择并恢复初始设置。
- 密码仍为最多 64 个当前批次候选，开始前可录入，失败后可主动展开补密；不自动弹窗或跨任务继承。
- 编码移入“更多选项”。新参数用于新批次；重试明确沿用原批次的输出、层数、编码和预算。
- 全局“打开结果”使用最近成功提交批次的实际产物位置，不随待开始输出框改变。单个成功顶层包直接打开该目录，多个成功顶层包打开其批次输出根。
- 结果树默认折叠，失败、发现中断、校验限制和清理残留另有可见摘要／问题入口。运行期间不抢选中项。

## 职责与验证方法

Headless 继续负责层数、密码池、重试判定和落盘。Document 负责呈现、用户意图及会话衔接；输出建议提取为无状态纯策略；View 只负责布局、焦点和原生文件适配。避免新通用框架和界面专属解压规则。

格式、递归与密码通过真实归档校验内容；测试替身只用于确定的取消时序与故障注入。增加有行为意义的默认值、状态、失败恢复与来源建议测试。渲染检查覆盖深浅主题、1180×760、800×600、640×520 等尺寸；实际截图必须查看。原生选择器、拖放与真实 DPI 有独立记录，不用 Headless 截图冒充原生验收。
