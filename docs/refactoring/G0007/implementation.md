# G0007 实施方案：简洁任务页与明确的结果恢复

日期：2026-09-07。对应[执行计划](plan.md)和[R01](../../roadmap/R01-simple-unpack-experience.md)。验证结论见[结果](result.md)。

## 职责与设计理由

| 位置 | 职责与取舍 |
| --- | --- |
| `OutputDirectorySuggestion` | 纯路径建议策略，无文件 I/O、无历史和容器依赖；只处理相同直接父目录 |
| `UnpackDocument.cs` | 原有创建／重试／扫描／关闭编排，补充本次输出根、扫描和取消呈现生命周期 |
| `UnpackDocument.Presentation.cs` | 输入、展开选项、递归开关、当前项、问题清单和产物入口的呈现投影 |
| `ArchiveNodeViewModel` | 稳定节点，按 Headless 错误类型投影补密／新批次入口，可重试性服从业务结果 |
| `UnpackView` | 单列滚动布局、固定操作栏、原生选择器、拖放与显式焦点导航 |
| `MainWindow` | 继续复用 Plugin，默认 900×760，最小 640×520，保持原关闭排空机制 |

SOLID 的落实是分离建议、执行和呈现，不为每个属性创建接口。继续依赖窄 `IUnpackService` 与 `IDocumentLifetime`；Headless 引擎、递归和密码策略不修改。呈现 partial 文件属于同一 Document，没有复制状态机、服务定位器或通用工作流框架。

## 输出建议与结果位置

文件经过原有 `InputDiscovery` 规范化后，批量更新建议：全部输入直接父目录相同才生成“解压结果”子路径。新增不同来源会清除自动建议；移除不同来源后可重新给出建议。显式编辑或通过选择器确认后，建议停止自动覆盖。空文本也代表编辑意图，清空批次才重置此状态。

选择器确认与文本属性 setter 分开，解决“用户确认与建议相同的值，属性没有变化通知”的情况。建议不创建目录，权限、链接、预算和写入沿用 Headless。

创建会话时记录本批次的输出根；单个成功顶层包的“打开结果”指向实际产物目录，多个成功顶层包则指向原批次根。后续编辑输出框或重试不改写它，避免进入空的新目录。

## 递归绑定边界

`IsRecursive` 映射既有 `MaxDepth`：关闭为 1，开启初次为 2，随后恢复本任务最后有效的 2–16 选择。`RecursiveDepth` 供数值控件绑定，确保隐藏控件的 Minimum=2 不会反向把默认 MaxDepth=1 改成 2。

非法 MaxDepth 的验证仍由 Headless 负责，不在 UI 中静默修正。清空后恢复一层和下次开启两层，不形成跨任务偏好。

## 结果与恢复

完整树默认折叠；失败、发现中断、校验警告和清理问题使用同一节点对象进入 `Issues`。快照不自动选择节点或抢焦点；点击问题才显示详情。密码操作展开候选并在布局就绪后聚焦；编码等错误导航到更多选项，再由用户开始新批次。

重试沿用旧输出、层数、编码和累计预算，只补充候选并重试允许项。成功后移除已恢复问题，不重复创建先前成功产物。

扫描、解压、取消等待分别显示状态；发出取消后禁用重复取消，直到实际工作退出才呈现终态。关闭代次检查继续保护迟到进度、选择器返回和焦点动作。选择器取消不再启动无意义的空输入扫描。

## 界面组织

空状态提供明显的拖入与添加入口；输入清单、密码、编码和完整树按需展开。结果区位于参数区前面；底部始终保留状态与可用操作。有成功产物时“打开结果”为强调按钮，“开始新批次”为次级动作。

详细入口与尺寸规则见[交互专项](interaction-design.md)，测试和原生检查边界见[验收矩阵](acceptance-matrix.md)。
