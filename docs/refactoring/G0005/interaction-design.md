# G0005 Document 交互与生命周期

一个普通 Document 管理一个当前批次，使用 `UnpackDocument / UnpackView`；没有 Tool、全局命令、Workflow、保存恢复或历史库。

## 页面与状态

顶部显示名称、开始和取消；参数区包含输出、深度、旧 ZIP 文件名编码和可展开的明文候选编辑器。中部左侧为输入，中央为默认展开的结果树，右侧为选中节点详情。底部显示已发现、已解压、失败、发现中断、按深度停止和累计展开量，不显示虚构的百分比。

| 状态 | 允许操作 | 界面行为 |
| --- | --- | --- |
| 空闲/未开始 | 添加、扫描、拖放、编辑、移除 | 无输入时不能开始 |
| 运行/扫描 | 取消，查看结果 | 参数/输入/清空/重复开始禁用 |
| 已完成/部分失败 | 查看输出、新批次、清空 | 成功项不开放重试；失败按核心资格判断 |
| 缺少密码 | 补充候选、重试所选 | 同一会话追加，结果节点身份不变 |
| 正在取消 | 等待核心退出 | 提示“正在取消”，不提前报告终态 |
| 已取消 | 查看成功输出、新批次/清空 | 不恢复暂停状态，不自动重跑取消节点 |
| 关闭 | 不再接受输入或回调 | 取消并排空核心/扫描任务，释放候选引用 |

错误文案包含字段名；失败前验证参数，非法新请求不会丢弃可检查的旧结果。执行参数是快照，输入框编辑不改变已运行会话的编码、深度或预算。

## UI 与文件系统适配

View 使用当前 TopLevel 的 StorageProvider 选择文件/文件夹，不把 Window 存入 Document。文件选择和拖放都经 `AddPathsAsync → InputDiscovery`，返回前再次检查生命周期。打开输出仅由用户点击触发，未有输出时按钮禁用。

InputDiscovery 后台扫描有界目录树，不跟随链接，排除选择的输出目录；多个相同路径只留一个。输入项简洁展示文件名，完整路径放在提示和节点详情。所有密码按明文编辑，提示清楚；开始/成功补密后清空编辑框，批次释放时清空密码池。

## 运行身份与关闭

Document 使用 UI SynchronizationContext 接收 Progress，并检查运行代次、IsBusy、关闭状态。结束推进代次，旧排队回调不能覆盖最终结果或新批次。没有静态回调或全局文档集合。

同步 Dispose 只排空不依赖 UI 的后台任务，避免 Host 在 UI 线程释放 Scope 时等待自身续体。Standalone 首次 Closing 先取消，等待初始化/会话和 Scope 退出，再真正关闭。重复关闭及具体/接口服务指向同一生命周期对象时的重复 Dispose 都可安全处理。

## 验证范围

自动化覆盖严格 DI Scope、两个 Document 同时运行且关闭一个不影响另一个、真实补密、参数失败、清空、新实例无历史、晚到回调防护；通过链接实际 Standalone 源码/AXAML 验证窗口关闭。

真实 View 在 1180×760 明暗、1000×600 明、800×600 暗下渲染；验证深度双向绑定、命令绑定和 Tab 导航，图像输出到 `artifacts/ui/`。已查看渲染图并修正深度输入框宽度和结果树展开。

原生文件/目录对话框、跨应用拖放、实际窗口 DPI 125%/150%/200% 仍需实机人工检查；Headless 渲染不代替这些场景。真实 Host 的 Dock、关闭、退出和 ALC 留到发布阶段验收。
